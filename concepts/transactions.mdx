Transactions are crucially important, in the PeoplesPay ecosystem. Collections and disbursements are two distinct types of transactions.

## Types of transactions

There are several different types of transactions within the PeoplesPay platform, but you will largely interact with [collections](/collections/) and [disbursements](/disbursements/). These have `transaction_type` values of `RM` and `SM` , respectively.

|Transaction type|`transaction_type`|Description|Access control|
|---|---|---|---|
|Collection|`RM`|Collect money from a real-world source into a PeoplesPay account; mobile money wallet or bank card|Merchant|
|Disbursement|`SM`|Send money from a PeoplesPay account to a real-world recipient; mobile money wallet or bank account|Merchant|
|Payout|`PY`|Send money from a PeoplesPay account to a bank account or mobile money wallet.|Admin-only|
|Settlement|`ST`|Settle collected funds from a PeoplesPay account to a verified associated bank account.|Admin-only|
|Direct credit|`DC`|Representation of off-platform inbound movement of funds to credit a merchant account.|Admin-only|
|Direct debit|`DB`|Representation of off-platform outbound movement of funds from debit of a merchant account.|Admin-only|

## Transaction statuses

Transactions (virtually across all types) will have the following statuses:
|Status|Explanation|
|---|---|
|paid|Transaction is paid.|
|failed|Transaction has failed.|
|pp|Transaction is pending (payment pending).|
|pc|Transaction has been debited from source, but hasn't been credited yet.|
|TCS-PENDING|Transaction is reported as pending (by GhIPSS). Applies to `SM`, `PY`, `ST` types.|

## Viewing single transaction data
<Warning>
Ensure you include your own transaction ID when executing transactions under the `externalTransactionId` field. That way you can track the transaction more comprehensively.
</Warning>

Transaction data is viewable via the merchant portal, via the API and when receiving webhook notifications.

### Viewing transaction data on the merchant portal

When accessing the merchant portal, you will the most recent transactions on the dashboard, when logging in. For any transaction, bring up the details by clicking on the eye icon:

![image](/images/merchant-1.png)
This will open a modal containing in-depth transaction information

### <mark>Accessing transaction data programmatically</mark>
To access in-depth transaction data via the API, call the `/transactions/get/{transactionId}` `GET` endpoint
```plaintext
curl 
--location 'https://peoplespay.com.gh/peoplepay/transactions/get/65673d042f1c500089973000' \
--header 'Authorization: Bearer <YOUR-MERCHANT-LOGIN-TOKEN>'
```

## Transaction history

You can retrieve transaction data in bulk over a specified time frame via the merchant portal or via the API. This is helpful for reconciliation purposes, analysis or to compare against your internal records.

### Accessing transaction history via the merchant portal

Get onto the **All transactions** page, and proceed to enter your date range using the date fields. Once you click **Filter transaction**, the platform will consolidate all your transactions and present them in the datatable on the same page. You can export the data by using the **Download report** function. If the transaction count for the selected date range exceeds 20,000, the rest of the records will be hidden from view. In such cases, downloading the report is the preferred option, as the generated CSV file will contain all transactions for that date range (i.e. up to and beyond the first 20,000).

<Warning>
    If you run into repeated timeout errors when trying to view transaction history, it may be that the transaction count for the selected date range is too large. Either reduce your date range to chunk the request, or reach out to [support](mailto:ppsupport@bsystemslimited.com) for large-scale bulk transaction history.
</Warning>

### Accessing transaction history via the API
To obtain transaction history programmatically, fire a <Badge color="green">GET</Badge> request to the `/hub/summary/filter` endpoint and pass in the required parameters
```plaintext
curl
--location 'https://peoplespay.com.gh/peoplepay/hub/summary/filter?id=63b59e41530aeeaec59a045f&startDate=10%2F1%2F2024&endDate=10%2F31%2F2024' \
--header 'Authorization: Bearer <YOUR-MERCHANT-LOGIN-TOKEN>'
```

The response will return transaction history as an array of <Tooltip headline="Transaction history format" tip="Transactions in the returned ">objects</Tooltip> in JSON format along with a link to the exported JSON in CSV format.
