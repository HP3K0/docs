There are two main types of authentication for PeoplesPay merchants: merchant login, and transaction token generation.

## Merchant login
During merchant onboarding, an email address must be registered, to which a generated password is sent for subsequent login to the [merchant portal](https://merchants.peoplespay.com.gh). A merchant login session can be created programmatically by calling the [`/login`](/api-reference/endpoint/merchant-login) endpoint with a [<Badge color="blue">POST</Badge> request](/api-reference/endpoint/merchant-login) containing the `email` and `password`. The returned `token` expires after 60 minutes. This authentication token is used for all API calls except transaction execution (i.e. [collecting](/api-reference/collections) or [disbursing](/api-reference/disbursements) funds)

## Token generation for transactions
Transaction execution, whether for a [collection](/concepts/transactions) or a [disbursement](/concepts/transactions) requires the creation of a separate authentication token. The type of transaction you wish to initiate will determine the operation to specify in the <Badge color="blue">POST</Badge> request payload.

<Note>
    Keep in mind that not all merchants can perform disbursements. For such merchants, using an `operation` value of `CREDIT` will cause the server
    to raise an error.
