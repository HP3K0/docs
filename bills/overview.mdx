The PeoplesPay platform supports bill payments, via a merchant account. The account must be funded to perform these operations. Bill payments operate on a **prepaid** basis.

## Bill categories
Payments can be performed for:
- utilities (water and electric)
- DSTV
- airtime and data bundles

For airtime and data bundles, purchases can be performed for `MTN`, `Telecel` (formerly Vodafone) and `AT` (aka AirtelTigo).

## Bill payment flow
To complete a bill payment, a number of steps must be followed, with some conditions.

<Tabs>
    <Tab title="General utilities">
        <Info>
            Note that the flow below applies to water utility and TV subscriptions.
        </Info>
        <Steps>
            <Step title="Get services">
                The first step is to query available services using the [/get-services](/api-reference/endpoint/get-billers) endpoint.
            </Step>
            <Step title="Lookup account">
                The account that is to be credited must be looked up by calling the [/lookup](/api-reference/endpoint/lookup-bill-account) endpoint. Use the `billServiceProviderId` and `billServiceProductId` values for the biller service returned in the previous step.
            </Step>
            <Step title="Get disbursement token (optional)">
                <Warning>
                    This step is optional only if a previously generated token hasn't yet expired.
                </Warning>
                To commit a bill payment, a dedicated auth token is required, generated by calling the [/token/get](/api-reference/endpoint/get-token) endpoint and setting the `operation` to `CREDIT`.
            </Step>
            <Step title="Commit">
                Specify the transaction details when calling the [/pay](/api-reference/endpoint/pay-bill) endpoint, to initiate the payment. Use the `sessionId` value returned in step 2, along with the biller service details from step 1.
            </Step>
            <Step title="Webhook call">
                The requester receives an HTTP notification at the specified webhook URL.
            </Step>
        </Steps> 
    </Tab>
    <Tab title="ECG">
        <Steps>
            <Step title="Get services">
                The first step is to query available services using the [/get-services](/api-reference/endpoint/get-billers) endpoint.
            </Step>
            <Step title="Lookup account">
                <Warning>
                    Account lookup can only be performed for prepaid meters. For other meter setups, look up using the [/ecg/get-meters-by-phone-number](/api-reference/endpoint/get-ecg-meters-by-phone-number) endpoint to retrieve the meterId
                </Warning>
                The account that is to be credited must be looked up by calling the [/lookup](/api-reference/endpoint/lookup-bill-account) endpoint. Use the `billServiceProviderId` and `billServiceProductId` values for the biller service returned in the previous step.
            </Step>
            <Step title="Check meter status">
                The current availability of the meter must then be checked, by calling the [/ecg/check-meter-status](/api-reference/endpoint/get-ecg-meter-status)
            </Step>
            <Step title="Get disbursement token (optional)">
                <Warning>
                    This step is optional only if a previously generated token hasn't yet expired.
                </Warning>
                To commit the ECG payment, a dedicated auth token is required, generated by calling the [/token/get](/api-reference/endpoint/get-token) endpoint and setting the `operation` to `CREDIT`.
            </Step>
            <Step title="Commit">
                Specify the transaction details when calling the [/pay](/api-reference/endpoint/pay-bill) endpoint, to initiate the payment. Use the `sessionId` value returned in step 2, along with the ECG biller service details returned in step 1.
            </Step>
            <Step title="Webhook call">
                The requester receives an HTTP notification at the specified webhook URL.
            </Step>
        </Steps>        
    </Tab>
    <Tab title="Airtime">
        <Steps>
            <Step title="Get disbursement token (optional)">
                <Warning>
                    This step is optional only if a previously generated token hasn't yet expired.
                </Warning>
                To perform the airtime purchase, a dedicated auth token is required, generated by calling the [/token/get](/api-reference/endpoint/get-token) endpoint and setting the `operation` to `CREDIT`.
            </Step>
            <Step title="Initiate purchase">
                Specify the network (`MTN`, `Telecel` or `AT`), the phone number and amount, then fire the API call.
            </Step>
            <Step title="Webhook call">
                The requester receives an HTTP notification at the specified webhook URL.
            </Step>
        </Steps>               
    </Tab>
    <Tab title="Data bundles">
        <Steps>
            <Step title="Query available data bundles">
                Check for available data bundles using the [/get-data-bundles](/api-reference/endpoint/get-data-bundles) endpoint
            </Step>
            <Step title="Get disbursement token (optional)">
                <Warning>
                    This step is optional only if a previously generated token hasn't yet expired.
                </Warning>
                To perform the data bundle purchase, a dedicated auth token is required, generated by calling the [/token/get](/api-reference/endpoint/get-token) endpoint and setting the `operation` to `CREDIT`.
            </Step>
            <Step title="Initiate purchase">
                Specify the network, the bundle name, the phone number and amount, then fire the API call to [/purchase-data-bundle](/api-reference/endpoint/purchase-data-bundle).
            </Step>
            <Step title="Webhook call">
                The requester receives an HTTP notification at the specified webhook URL.
            </Step>
        </Steps>
    </Tab>
</Tabs>



## Management
Bill payment transactions show up with a `transactionType` of `PB` in tranasaction history. Airtime topups have a `transactionType` of `AT`, whilst data bundle purchases are labelled as `DBP`. As such, look out for those entries when [retrieving transaction history](/api-reference/endpoint/get-transactions).
