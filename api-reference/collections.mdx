Collection transactions are initiated by calling the API to collect money from an end-user. We currently support mobile money and bank card payment channels:
- MTN
- Telecel
- AT
- Mastercard
- VISA

<Info>
If you plan to collect international (i.e. non-Ghanaian) cards and are experiencing difficulties, discuss that with your onboarding manager or [contact support](mailto:ppsupport@bsystemslimited).
</Info>

## The collection object in events
The [full transaction object](/api-reference/transactions) is truncated when included in events and delivered in the webhook notifcation payload.

### Properties
<ResponseField name="amount" type="number">Amount credited to merchant account.</ResponseField>
<ResponseField name="status" type="string"><Tooltip headline="Transaction status" tip="The authoritative field of a transaction's status. Account credit actions are taken based on this value." cta="Read full reference" href="/concepts/transactions">Status</Tooltip> of transaction.</ResponseField>
<ResponseField name="date" type="string">Date of collection transaction creation, in-database. ISO timestamp format.</ResponseField>
<ResponseField name="message" type="string">Accompanying reason for transaction status. Specific error messages for failed transaction statuses will be visible here.</ResponseField>
<ResponseField name="externalTransactionId" type="string">Merchant-supplied transaction ID for tracking.</ResponseField>
### More properties
<ResponseField name="eventId" type="string"><Expandable title="description">ID of emitted webhook event.</Expandable></ResponseField>
<ResponseField deprecated name="code" type="string" post={["DO NOT USE"]}><Expandable title="description">_Deprecated; will be removed._ Zero-padded numeric code associated with server operation.</Expandable></ResponseField>
<ResponseField deprecated name="success" type="boolean" default="true"><Expandable title="description">_Deprecated; will be removed._ Boolean field specifying whether the server operation was successful. Value is always `true` in event payloads.</Expandable></ResponseField>

## Related events

## Endpoints
|Method|Path|Description|
|---|---|---|
|<Badge color="blue">POST</Badge>|[`/hub/token/get`](/api-reference/endpoint/get-token-collection)|Generate bearer token for collection request|
|<Badge color="blue">POST</Badge>|[`/hub/collectmoney`](/api-reference/endpoint/collect-momo)|Initiate collection via mobile money channel|
|<Badge color="blue">POST</Badge>|[`/hub/collectmoney/card`](/api-reference/endpoint/collect-card)|Initiate collection via bank card|
|<Badge color="blue">POST</Badge>|[`/api/checkout/redirect/init`](/api-reference/endpoint/collect-checkout)|Initiate collection via hosted checkout|

<Danger>
Collections are fully asynchronous. The synchronous HTTP response you receive when calling [`/hub/collectmoney`](/api-reference/endpoint/collect-momo) or [`/hub/collectmoney/card`](/api-reference/endpoint/collect-card) simply indicates whether PeoplesPay has successfully received your request for processing. ALWAYS wait for the webhook notification before making any updates in your application.
</Danger>

## How to: performing an API collection
<Steps>
<Step>
Call <Badge color="green">GET</Badge> `/hub/token/get`. Set `operation` in the request payload to `"DEBIT"`. The resulting authentication token can be used for up to 60 minutes before having to request a fresh one.
</Step>
<Step>
Call <Badge color="blue">POST</Badge> `/hub/collectmoney` or `/hub/collectmoney/card`. Use the token obtained in step 1 as the `Bearer` token value.
</Step>
<Step>
Wait for the webhook notification at the supplied `callbackUrl`
</Step>
</Steps>

<Note>
For hosted checkout, no token authentication is required.
</Note>
