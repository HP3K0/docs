Disbursement transactions are initiated by calling the API to disburse money to an end-user. We currently support disbursing to mobile money wallets and bank accounts. For a complete list of supported mobile money operators and bank destinations, please refer to the [table of account issuers](/concepts/account-issuers).

## The disbursement object in events
The [full transaction object](/api-reference/transactions) is truncated when included in events and delivered in the webhook notifcation payload.

### Properties
<ResponseField name="transactionId" type="string">PeoplesPay transaction ID.</ResponseField>
<ResponseField name="amount" type="number">Amount sent to recipient.</ResponseField>
<ResponseField name="status" type="string"><Tooltip headline="Transaction status" tip="The authoritative field of a transaction's status. ## Related events
- `transaction.status.updated` - Fired when the status of a disbursement is updated. See [event reference](/api-reference/events).

## Endpoints
|Method|Path|Description|
|---|---|---|
|<Badge color="blue">POST</Badge>|[`/hub/token/get`](/api-reference/endpoint/get-token-disbursement)|Generate bearer token for disbursement request|
|<Badge color="blue">POST</Badge>|[`/hub/disburse`](/api-reference/endpoint/disburse)|Initiate disbursement via mobile money channel|



<Danger>
Disbursements are synchronous. The HTTP response you receive when calling [`/hub/disburse`](/api-reference/endpoint/disburse) indicates whether PeoplesPay has successfully received your request and passed it on for processing. Nonetheless, ALWAYS wait for the webhook notification before making any updates in your application.
</Danger>

## How to: performing a disbursement
<Steps>
<Step>
Call <Badge color="green">GET</Badge> `/hub/token/get`. Set `operation` in the request payload to `"CREDIT"` The resulting authentication token can be used for up to 60 minutes before having to request a fresh one.
</Step>
<Step>
Call <Badge color="blue">POST</Badge> `/hub/disburse`. Use the token obtained in step 1 as the `Bearer` token value.
</Step>
<Step>
Wait for the webhook notification at the supplied `callbackUrl`
</Step>
</Steps>
